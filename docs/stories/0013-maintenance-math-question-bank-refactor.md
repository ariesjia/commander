# 机甲维修：一年级数学题库整体重构

> **概述**：在 [0007-student-daily-maintenance-math](./0007-student-daily-maintenance-math.md) 已落地的「机甲维修」闭环上，将当前仅限 **0–20 内加减 / 连加减（中间结果 0–20）** 的出题器，重构为**人教版小学一年级**常见题型与口算范围（见下文单元对齐）；保持**每日一次、无积分、服务端重算答案、叙事仍避免「考试/测验」**等产品约束不变。
> **本期交付范围**：仅 **P0 + P1**（见第 6 节）。钟表、人民币、图形计数等 **P2/P3** 不包含在本 story 验收内，可留在后续 story。
> **现状**：`src/lib/maintenance-math/` 中 `MaintenanceQuestion` 仅 `binary` 与 `chain`；`isValidQuestion` 与 `numToZh` 均硬编码 0–20；学生页仅用数字键盘提交**单个整数答案**。

**关联**：`docs/PRD-机甲指挥官-学生游戏化激励系统.md`；实现文件 `src/lib/maintenance-math/*`、`src/app/student/maintenance-math/page.tsx`、`src/app/api/student/maintenance-math/*`。

## 1. 用户故事

**作为** 学生  
**我想要** 在「机甲维修」里练习**与一年级课堂更接近**的多种口算与简单数理题（不仅是 20 以内两步算式）  
**以便** 用同一套有趣叙事覆盖本学期常见的计算与简单应用

**作为家长 / 产品**  
**我想要** 题库按**人教版一年级**常见类型可配置、可迭代，且升级出题器后**旧日志仍可辨认版本**（`generatorId` / `version`）  
**以便** 后续加减难度或与校内进度对齐时不需再做大拆大修

## 2. 验收标准（Acceptance Criteria）

- [ ] **题型覆盖（P0 + P1）**：每日工单须覆盖第 3 节表中 **P0 / P1** 行所列类型——**100 以内加减口算**、**连加减**（从左到右，中间结果上界可配置）、**比大小**、**填空求未知数**、**简单一步应用题**、**找规律填数**。本 story **不验收** 钟表、人民币、纯配图分类计数（P2/P3）。
- [ ] **加减题卫生规则（必达）**：凡题目中出现「一步加减」（含两数题与连算中的**每一步**），须同时满足：
  - **禁止加零 / 减零**：不得出现 `a + 0`、`a - 0`（右操作数为 `0` 的加、减）。
  - **禁止 a−a**：两数减法不得 `a === b`；连算中不得出现「当前累计值减去与其**相等**的下一项」（即禁止一步之内等价于 `acc - acc`）。
  - **禁止最左数为 0（题面）**：两数题左操作数 `a !== 0`（不得出现 `0 + n`、`0 - n`）；连算 **`nums[0] !== 0`**。答案或中间过程仍可为 0，仅限制**题面从左起第一个数**不为 0。
  - **波及题型**：以上规则适用于 **binary / chain**；**比大小**题中若两侧为算式，两侧子式须同上；**求未知数**、`□` 不在最左且生成时过滤能使最左项为 0 的无效组合；**应用题**对应的列式最左项也不为 0。
- [ ] **数据模型**：`MaintenanceQuestion`（或等价 union）能表达各题型；`expectedAnswer` 与 `isValidQuestion`（或分题型校验器）与题型同步扩展；**同 `studentId + dateKey + generatorId + version`** 仍 Deterministic。
- [ ] **API 契约**：`GET session` 下发的题目 DTO 包含题型 discriminant，前端可按类型渲染；`POST complete` 仍只接受**与当前 generator 重算一致**的答案序列（答案可为整数或扩展为结构化字段，需版本化与校验一致）。
- [ ] **UI**：除纯算式外，新增题型有清晰题面（比大小、填空、应用题文案）；触控数字键盘**允许的最大位数**与**100 以内 / 更长叙述**匹配（例如必要时支持 3 位非负整数或分步交互）。
- [ ] **朗读 TTS**：`buildArithmeticSpeech` 或继任 API 覆盖新题型普通话朗读（至少文本题与应用题；图形类可仅 Alt 文本或 P2）。
- [ ] **配置**：`src/config/maintenance-math.ts` 中 `MAINTENANCE_MATH_GENERATOR_ID` / `VERSION` 随破坏性变更递增；`GeneratorConfig` 可配置**各题型占比、难度上界、是否启用某类题**。
- [ ] **校验脚本**：`scripts/verify-maintenance-math.ts` 扩展为抽样或性质检验（无死题、答案在声明范围内、**无 +0 / -0 / a−a / 连算等价禁用步 / 题面最左数为 0** 等）。
- [ ] **回归**：家长开关、每日一次、无积分、`StudentMaintenanceMathLog` 字段语义不变（除非另开 story 扩展列）。

### 4.2 数据库设计（Database Design）

- **本期可不迁移**：沿用 `StudentMaintenanceMathLog.generatorId`、`sessionHash` 区分版本即可。
- 若未来需按**题型统计正确率**，可另开 story 增加 JSON 列 `perQuestionStats`；**本 story 不强制**。

### 4.3 前端设计（Frontend Design）

- **路由**：仍为 `src/app/student/maintenance-math/page.tsx`。
- **算式类**：延续大号数字与 `+` / `-` 排版；链式题在窄屏保持可读（已有 wrap）。
- **比大小**：中间 `○` 处用三个横向按钮「＜」「＝」「＞」或映射到内部整数码，避免误触。
- **应用题**：卷内卡片展示 2～4 行文字，标题区仍为「第 N 步检修」；不打断叙事用词规范（见 0007）。
- **键盘**：纯数字题保留 0–9；比大小可用独立按钮减少模式切换成本。

## 5. 依赖与风险

- **依赖**：0007 的 TTS、每日一次、`getTodayStr` 与时区策略不变。
- **风险**：题型变多后 **session 体量与朗读时间**变长——可通过 `questionCount` 或分类占比配置折中。
- **风险**：`answers` 若从纯 `number[]` 扩展为联合类型，需**前后端同时版本化**，避免旧客户端与新 API 混用（若仅有 Web 且同发版，可一次改完）。
